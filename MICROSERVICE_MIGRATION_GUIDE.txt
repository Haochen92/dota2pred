🐳 STAGE 3: DOCKER & POETRY INTEGRATION
===============================================================================

WHY POETRY INSTEAD OF PIP?

1. Dependency Resolution: Poetry resolves version conflicts automatically
2. Lock Files: poetry.lock ensures reproducible builds
3. Virtual Environment Management: Better isolation
4. Development Dependencies: Clear separation of dev vs production deps
5. Package Management: Handles local package dependencies elegantly

DOCKER BUILD PROCESS BREAKDOWN

Let's examine the prediction service Dockerfile in detail:

FROM python:3.11-slim

WORKDIR /app

# 1. Install system dependencies
RUN apt-get update && apt-get install -y \
    gcc \
    && rm -rf /var/lib/apt/lists/*

# 2. Install poetry
RUN pip install poetry

# 3. Configure poetry: don't create virtual env, install deps to system python
RUN poetry config virtualenvs.create false

# 4. Copy shared packages first and install them
COPY packages/ ./packages/
RUN cd packages/dota_oracle_common && poetry install --only=main --no-interaction

# 5. Copy service poetry files and install dependencies
COPY services/prediction_service/pyproject.toml services/prediction_service/pyproject.toml
RUN cd services/prediction_service && poetry install --only=main --no-interaction

# 6. Copy application code
COPY services/prediction_service/src/ ./src/
COPY services/prediction_service/models/ ./models/
COPY services/prediction_service/requirements.txt ./requirements.txt
COPY services/prediction_service/save_model.py ./save_model.py

# 7. Set Python path to include shared packages
ENV PYTHONPATH=/app/packages/dota_oracle_common/src:/app/src

# 8. Save the model to BentoML store
RUN python save_model.py

EXPOSE 3000
CMD ["bentoml", "serve", "src.service:svc", "--host", "0.0.0.0", "--port", "3000"]

INSTALLATION SEQUENCE ANALYSIS

Step-by-Step Installation Process:

1. Base Image Setup
   FROM python:3.11-slim
   WORKDIR /app

2. System Dependencies
   RUN apt-get update && apt-get install -y gcc && rm -rf /var/lib/apt/lists/*
   - gcc: Required for compiling Python packages with C extensions
   - Clean up apt cache to reduce image size

3. Poetry Installation
   RUN pip install poetry
   RUN poetry config virtualenvs.create false
   - Install Poetry globally with pip
   - Disable virtual environment creation (install directly to system Python)

4. Shared Package Installation
   COPY packages/ ./packages/
   RUN cd packages/dota_oracle_common && poetry install --only=main --no-interaction
   - Copy shared packages first (better Docker layer caching)
   - Install shared dependencies before service-specific ones
   - --only=main: Skip development dependencies
   - --no-interaction: Non-interactive mode for CI/CD

5. Service-Specific Dependencies
   COPY services/prediction_service/pyproject.toml services/prediction_service/pyproject.toml
   RUN cd services/prediction_service && poetry install --only=main --no-interaction
   - Copy service pyproject.toml to correct relative path context
   - Install service dependencies (including references to shared packages)

🔧 STAGE 4: DEPENDENCY RESOLUTION & PATH MANAGEMENT
===============================================================================

PATH REFERENCE RESOLUTION

The key challenge was handling relative paths in pyproject.toml within Docker context:

Problem:
# This path is relative to the service directory
dota-oracle-common = {path = "../../packages/dota_oracle_common", develop = true}

Solution:
# Copy to maintain directory structure
COPY services/prediction_service/pyproject.toml services/prediction_service/pyproject.toml

# Change to service directory to maintain relative paths
RUN cd services/prediction_service && poetry install --only=main --no-interaction

PYTHONPATH CONFIGURATION

ENV PYTHONPATH=/app/packages/dota_oracle_common/src:/app/src

This ensures Python can find:
- Shared packages: from dota_oracle_common.models import ...
- Service code: from api_service.main import ...

===============================================================================
📦 STAGE 5: PACKAGE MODE CONFIGURATION
===============================================================================

THE PACKAGE-MODE = FALSE SETTING

This was crucial for services that don't need to be packaged themselves:

[tool.poetry]
name = "prediction-service"
package-mode = false  # Only dependency management, not packaging

Why this was needed:
- Services are applications, not libraries
- We only want dependency management, not package creation
- Avoids Poetry trying to find package source code during poetry install
- Prevents "No file/folder found for package" errors

🎯 STAGE 8: PROBLEM RESOLUTION & SOLUTIONS
===============================================================================

COMMON ISSUES ENCOUNTERED & SOLUTIONS

1. Path Resolution in Docker:
Problem: Path /packages/dota_oracle_common for dota-oracle-common does not exist
Solution: Maintain directory structure in Docker context
COPY services/prediction_service/pyproject.toml services/prediction_service/pyproject.toml
RUN cd services/prediction_service && poetry install

2. Package Mode Issues:
Problem: "No file/folder found for package prediction-service"
Solution: Add package-mode = false to pyproject.toml

3. PostgreSQL Dependencies:
Problem: psycopg2 build failure
Solution: Add system dependencies
RUN apt-get update && apt-get install -y libpq-dev

4. BentoML Service Definition:
Problem: AttributeError: 'MatchPredictionService' object has no attribute 'name'
Solution: Use class reference, not instance
svc = MatchPredictionService  # Not MatchPredictionService()
